# AI 软件测试平台 MVP 需求范围说明

## 1. MVP 定位

第一版 MVP 建议定位为“AI 测试设计平台”，核心验证用户是否愿意把需求文档交给平台，并接受平台生成的测试点和测试用例作为工作起点。

第一版不追求覆盖完整测试管理系统，也不急于做复杂自动化执行。优先把“需求文档到高质量测试用例”的链路做稳定。

## 2. MVP 核心目标

- 支持测试项目创建和基础管理。
- 支持上传需求、原型、接口文档和变更说明。
- 支持 AI 解析需求，输出模块、功能点、业务规则和待确认问题。
- 支持 AI 生成测试点。
- 支持 AI 生成测试用例。
- 支持人工编辑和评审用例。
- 支持导出标准 Excel 用例表。
- 支持测试资产在项目内沉淀。

## 3. MVP 用户路径

```text
创建项目
→ 上传需求资料
→ 启动 AI 需求解析
→ 查看并确认待确认问题
→ 生成测试点
→ 生成测试用例
→ 人工编辑和评审
→ 导出 Excel
```

## 4. MVP 功能清单

| 模块 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| 项目管理 | 创建项目 | P0 | 输入项目名称、版本、负责人、测试类型 |
| 项目管理 | 项目列表 | P0 | 查看项目状态、最近更新时间、负责人 |
| 文件管理 | 上传需求文档 | P0 | 支持 Word、PDF、Excel、Markdown |
| 文件管理 | 上传接口文档 | P1 | 可先支持 OpenAPI/Swagger 或 Markdown |
| AI 需求解析 | 提取模块和功能点 | P0 | 输出结构化需求解析表 |
| AI 需求解析 | 提取业务规则 | P0 | 标记规则、输入、输出、异常 |
| AI 需求解析 | 生成待确认问题 | P0 | 对不清晰内容标记为待确认 |
| 测试点管理 | 生成测试点 | P0 | 覆盖正常、异常、边界、权限、数据一致性 |
| 测试点管理 | 测试点编辑 | P0 | 支持新增、修改、删除 |
| 用例管理 | 生成测试用例 | P0 | 根据测试点生成可执行用例 |
| 用例管理 | 用例编辑 | P0 | 支持表格编辑 |
| 用例管理 | 用例评审状态 | P1 | 待评审、已通过、需修改 |
| 用例管理 | 自动化标识 | P1 | 标记是否适合自动化 |
| 导出 | Excel 导出 | P0 | 导出标准测试用例表 |
| 导出 | Markdown 导出 | P2 | 便于评审或归档 |
| 权限 | 简单角色 | P2 | 管理员、测试人员、只读人员 |

## 5. 暂不纳入 MVP 的能力

| 功能 | 暂缓原因 |
|---|---|
| 自动化脚本执行 | 需要执行环境、浏览器、CI/CD 和脚本稳定性支撑 |
| 元素定位自修复 | 依赖页面结构采集和执行失败数据 |
| 缺陷系统集成 | 需要对接禅道、Jira、TAPD 等外部系统 |
| 复杂权限体系 | 第一版先验证核心测试设计价值 |
| 多租户计费 | 不影响第一阶段产品闭环 |
| 质量预测模型 | 需要历史执行和缺陷数据积累 |

## 6. 关键页面

### 6.1 项目列表

字段：

- 项目名称。
- 当前版本。
- 测试类型。
- 负责人。
- 用例数量。
- AI 解析状态。
- 最近更新时间。

### 6.2 项目详情

Tab 建议：

```text
项目概览
输入资料
需求解析
测试点
测试用例
导出记录
```

### 6.3 需求解析页

能力：

- 查看上传文件。
- 发起 AI 解析。
- 查看模块和功能点。
- 查看业务规则。
- 查看待确认问题。
- 人工修改解析结果。

### 6.4 测试点页

能力：

- 一键生成测试点。
- 按模块筛选。
- 按风险等级筛选。
- 编辑测试点。
- 标记优先级。
- 关联需求编号。

### 6.5 测试用例页

能力：

- 从测试点生成用例。
- 表格化编辑。
- 批量修改优先级。
- 批量修改评审状态。
- 标记自动化候选。
- 导出 Excel。

## 7. 测试用例标准字段

| 字段 | 是否必填 | 说明 |
|---|---|---|
| 用例编号 | 是 | 按模块命名，例如 TC_LOGIN_001 |
| 所属模块 | 是 | 对应需求模块 |
| 功能点 | 是 | 对应具体功能 |
| 用例标题 | 是 | 描述验证目标 |
| 优先级 | 是 | P0/P1/P2/P3 |
| 前置条件 | 是 | 执行前状态 |
| 测试步骤 | 是 | 使用步骤化描述 |
| 测试数据 | 否 | 输入数据或准备数据 |
| 预期结果 | 是 | 可判断的验证结果 |
| 自动化标识 | 否 | 是/否/待评估 |
| 需求来源 | 是 | 关联需求编号 |
| 评审状态 | 是 | 待评审/已通过/需修改 |
| 备注 | 否 | 补充说明 |

## 8. AI 输出质量规则

- 需求中没有的信息不能编造成事实。
- 不确定内容必须标记为“待确认”。
- 每条用例必须关联需求来源。
- 测试步骤必须可执行。
- 预期结果必须明确可判断。
- 一条用例只验证一个主要目标。
- 异常、边界、权限和数据一致性场景必须重点覆盖。
- 自动化候选用例应优先选择稳定、高价值、可重复执行的场景。

## 9. MVP 验收标准

| 验收项 | 标准 |
|---|---|
| 文档上传 | 能上传并管理需求资料 |
| 需求解析 | 能输出模块、功能点、规则和待确认问题 |
| 测试点生成 | 能按模块生成结构化测试点 |
| 用例生成 | 能生成字段完整、步骤可执行、预期可判断的用例 |
| 人工编辑 | 能在线修改 AI 生成内容 |
| Excel 导出 | 导出的用例表可正常在 Excel/WPS 中阅读 |
| 追溯关系 | 用例能追溯到需求来源 |

## 10. 第一版成功指标

- 测试人员生成首版测试用例的时间降低 50% 以上。
- AI 生成用例经人工调整后可采纳比例达到 70% 以上。
- 需求解析出的待确认问题对评审有实际帮助。
- 导出的测试用例表能直接进入团队现有评审和执行流程。
