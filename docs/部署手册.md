# AITestLink 部署手册

## 一、服务器环境要求

| 组件 | 要求 |
|------|------|
| 操作系统 | Ubuntu 20.04+ / Debian 11+ |
| Python | 3.10+ |
| Node.js | 18+ |
| 包管理器 | pnpm |
| 进程管理 | PM2 |
| Web 服务器 | Nginx |
| SSL | Let's Encrypt（推荐） |

## 二、服务器目录结构

```
/opt/aitestlink/
├── frontend/          ← 构建后的前端静态文件
│   ├── dist/          ← vite build 产物
│   ├── src/
│   ├── package.json
│   └── ...
├── server/            ← FastAPI 后端
│   ├── app/
│   ├── venv/          ← Python 虚拟环境
│   ├── uploads/       ← 用户上传文件（头像、文档等）
│   ├── aitestlink.db  ← SQLite 数据库文件
│   ├── .env           ← 生产环境配置
│   └── requirements.txt
└── ...
```

## 三、首次部署

### 3.1 服务器初始化

```bash
# SSH 登录服务器
ssh root@116.62.247.82

# 创建项目目录
mkdir -p /opt/aitestlink

# 安装 Node.js（如未安装）
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt-get install -y nodejs

# 安装 pnpm
npm install -g pnpm

# 安装 Python 虚拟环境（如未安装）
apt-get install -y python3-venv python3-pip

# 创建 Python 虚拟环境
cd /opt/aitestlink/server
python3 -m venv venv
source venv/bin/activate

# 安装后端依赖
pip install -r requirements.txt
pip install bcrypt gunicorn
```

### 3.2 同步代码到服务器

```bash
# 在本地执行
rsync -avz --delete \
  --exclude 'node_modules' \
  --exclude '.git' \
  --exclude 'dist' \
  --exclude '.vite' \
  --exclude 'venv' \
  --exclude '*.db' \
  --exclude 'server/uploads/' \
  /Users/yuhuai/AI-APP/CodeX/AITestLink/ \
  root@116.62.247.82:/opt/aitestlink/
```

### 3.3 配置后端环境变量

在服务器上编辑 `/opt/aitestlink/server/.env`：

```bash
# 数据库（SQLite，无需额外安装）
DATABASE_URL=sqlite+aiosqlite:///./aitestlink.db

# LLM API 配置（按实际使用的模型填写）
LLM_API_KEY=your-api-key-here
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o

# 文件上传目录
UPLOAD_DIR=./uploads

# 跨域配置（生产环境域名）
CORS_ORIGINS=https://www.aimstong.com,http://www.aimstong.com

# JWT 密钥（必须修改为强随机字符串）
JWT_SECRET=your-production-jwt-secret-here

# 后端基础 URL
BASE_URL=http://localhost:8001
```

### 3.4 构建前端

```bash
# 在服务器上执行
cd /opt/aitestlink/frontend

# 安装依赖
pnpm install

# 构建（跳过 TypeScript 类型检查，避免测试文件导致的报错）
VITE_API_BASE=/aitestlink/api npx vite build
```

> **注意**：不要使用 `pnpm build`，因为它会执行 `tsc -b`，而项目中存在一些测试文件的类型错误。直接用 `npx vite build` 跳过类型检查。

### 3.5 启动后端服务

```bash
# 在服务器上执行
cd /opt/aitestlink/server

# 确保 venv 中安装了 gunicorn
/opt/aitestlink/server/venv/bin/pip install gunicorn bcrypt

# 使用 PM2 启动
pm2 start gunicorn \
  --name aitestlink-server \
  --bind 0.0.0.0:8001 \
  --workers 4 \
  --worker-class uvicorn.workers.UvicornWorker \
  --chdir /opt/aitestlink/server \
  -- venv/bin/python -m app.main:app

# 或者使用 uvicorn 直接启动（开发/调试用）
pm2 start /opt/aitestlink/server/venv/bin/uvicorn \
  --name aitestlink-server \
  -- app.main:app \
  --host 0.0.0.0 \
  --port 8001 \
  --reload

# 保存 PM2 进程列表（开机自启）
pm2 save
pm2 startup
```

> **重要**：gunicorn 的 `--chdir` 必须指向项目根目录，worker 命令使用 venv 中的 Python 路径。

### 3.6 配置 Nginx

在 `/etc/nginx/sites-available/aitestlink`（或已有的 mianshitong 配置中追加）：

```nginx
# AITestLink 子路径部署
# 前端静态文件
location /aitestlink/ {
    alias /opt/aitestlink/frontend/dist/;
    try_files $uri $uri/ /aitestlink/index.html;

    # 静态资源缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}

# 后端 API 代理
location /aitestlink/api/ {
    rewrite ^/aitestlink/api/(.*)$ /api/$1 break;
    proxy_pass http://127.0.0.1:8001;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    # AI 请求可能耗时较长
    proxy_read_timeout 300s;
    proxy_send_timeout 300s;
}

# 上传文件访问
location /aitestlink/uploads/ {
    alias /opt/aitestlink/server/uploads/;
    expires 7d;
    add_header Cache-Control "public";
}
```

> **Nginx rewrite 关键**：`rewrite ^/aitestlink/api/(.*)$ /api/$1 break;` 必须保留 `/api` 前缀，否则 FastAPI 路由匹配会 404。

### 3.7 配置 HTTPS（SSL）

```bash
# 安装 Certbot（如未安装）
apt-get install -y certbot python3-certbot-nginx

# 申请证书
certbot --nginx -d www.aimstong.com -d aimstong.com

# 自动续期
certbot renew --dry-run
```

### 3.8 重载 Nginx 并验证

```bash
# 测试 Nginx 配置
nginx -t

# 重载
nginx -s reload

# 验证后端健康
curl -sk https://127.0.0.1/aitestlink/api/health -H 'Host: www.aimstong.com'

# 验证前端页面
curl -sk https://127.0.0.1/aitestlink/ -H 'Host: www.aimstong.com' | head -5
```

## 五、子路径部署注意事项

AITestLink 部署在 `https://www.aimstong.com/aitestlink/` 子路径下，涉及三个地方必须同步修改：

### 5.1 vite.config.ts — 构建基础路径

生产构建时需要设置 `base`。有两种方式：

**方式一**：在 `vite.config.ts` 中添加（推荐）
```ts
export default defineConfig({
  base: "/aitestlink/",   // ← 添加此行
  // ...
})
```

**方式二**：构建时通过环境变量（当前使用的方式）
```bash
VITE_API_BASE=/aitestlink/api npx vite build
```

### 5.2 BrowserRouter — 路由基础路径

在 `frontend/src/main.tsx` 中：
```tsx
<BrowserRouter basename="/aitestlink">
```

### 5.3 API 请求地址

在 `frontend/src/api/client.ts` 中：
```ts
const API_BASE = import.meta.env.VITE_API_BASE || "/api";
```

在 `frontend/src/features/auth/api/client.ts` 中：
```ts
const BASE_URL = "/api";
```

> 开发环境（`pnpm dev`）通过 Vite proxy 转发 `/api` 到后端，无需子路径前缀。
> 生产环境通过 `VITE_API_BASE=/aitestlink/api` 构建，Nginx 再将 `/aitestlink/api/` 转发到后端。

## 七、常见问题排查

### 7.1 前端刷新 404

**原因**：Nginx 未配置 `try_files` 回退到 `index.html`。

**解决**：确保 location 配置中有：
```nginx
try_files $uri $uri/ /aitestlink/index.html;
```

### 7.2 API 请求 404

**原因**：Nginx rewrite 规则剥离了 `/api` 前缀。

**解决**：确保 rewrite 保留 `/api`：
```nginx
rewrite ^/aitestlink/api/(.*)$ /api/$1 break;
```

### 7.3 登录页面验证码不显示

**原因**：前端 auth 模块的 API 地址硬编码为 `/api`，未使用子路径前缀。

**解决**：`frontend/src/features/auth/api/client.ts` 中的 `BASE_URL` 应使用环境变量：
```ts
const BASE_URL = import.meta.env.VITE_API_BASE || "/api";
```

### 7.4 后端启动报 bcrypt 找不到

**原因**：bcrypt 安装到了系统 Python 而非 venv。

**解决**：
```bash
/opt/aitestlink/server/venv/bin/pip install bcrypt
```

### 7.5 CORS 跨域错误

**原因**：`.env` 中 `CORS_ORIGINS` 未包含生产域名。

**解决**：
```env
CORS_ORIGINS=https://www.aimstong.com,http://www.aimstong.com,http://localhost:5173
```

### 7.6 部署后代码不是最新版

**原因**：同步了错误的本地目录。

**解决**：确认本地源码目录为 `/Users/yuhuai/AI-APP/CodeX/AITestLink`（CodeX 目录），而非其他副本。同步前可对比 git log：
```bash
cd /Users/yuhuai/AI-APP/CodeX/AITestLink && git log --oneline -5
```

### 7.7 vite.config.js 覆盖 vite.config.ts

**原因**：服务器上残留了旧的 `vite.config.js` 文件，优先级高于 `.ts`。

**解决**：
```bash
cd /opt/aitestlink/frontend
rm -f vite.config.js vite.config.d.ts
```

## 八、一键部署脚本（可选）

将以下脚本保存为 `deploy.sh` 放在项目根目录：

```bash
#!/bin/bash
set -e

SERVER="root@116.62.247.82"
REMOTE_DIR="/opt/aitestlink"

echo ">>> 1. 同步代码到服务器..."
rsync -avz --delete \
  --exclude 'node_modules' \
  --exclude '.git' \
  --exclude 'dist' \
  --exclude '.vite' \
  --exclude 'venv' \
  --exclude '*.db' \
  --exclude 'server/uploads/' \
  ./ \
  ${SERVER}:${REMOTE_DIR}/

echo ">>> 2. 服务器上构建前端..."
ssh ${SERVER} << 'EOF'
cd /opt/aitestlink/frontend
rm -rf dist .vite node_modules/.vite
pnpm install --frozen-lockfile 2>/dev/null || pnpm install
VITE_API_BASE=/aitestlink/api npx vite build
EOF

echo ">>> 3. 服务器上更新后端依赖..."
ssh ${SERVER} << 'EOF'
cd /opt/aitestlink/server
/opt/aitestlink/server/venv/bin/pip install -r requirements.txt
/opt/aitestlink/server/venv/bin/pip install bcrypt gunicorn
EOF

echo ">>> 4. 重启后端服务..."
ssh ${SERVER} "pm2 restart aitestlink-server"

echo ">>> 5. 验证..."
ssh ${SERVER} "curl -sk https://127.0.0.1/aitestlink/api/health -H 'Host: www.aimstong.com'"

echo ">>> 部署完成！"
echo ">>> 访问地址：https://www.aimstong.com/aitestlink/"
```

使用方式：
```bash
chmod +x deploy.sh
./deploy.sh
```
