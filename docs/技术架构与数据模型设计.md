# AI 软件测试平台技术架构与数据模型设计

> 更新时间：2026年7月10日

## 1. 架构目标

技术架构需要支持 AI 任务编排、文档解析、测试资产管理、自动化执行和质量数据分析。第一版应保持架构清晰，避免过早复杂化；但核心数据链路必须从一开始设计完整。

核心链路：

```text
需求 → 测试点 → 测试用例 → 执行记录 → 缺陷 → 回归记录 → 测试报告
```

## 2. 总体架构

```text
前端应用 (React + TypeScript + Vite)
  ├─ 首页驾驶舱 (Dashboard)
  ├─ 项目空间 (Projects)
  ├─ 测试中心 (Test Center)
  ├─ 文档中心 (Document Center)
  ├─ 文档配置 (Doc Config)
  ├─ 模型配置 (Model Config)
  ├─ 用户管理 (User Management)
  └─ 个人设置 (Personal Settings)

后端服务 (FastAPI + SQLAlchemy Async)
  ├─ 认证服务 (Auth)
  ├─ 项目服务 (Projects)
  ├─ 文件服务 (Files)
  ├─ 需求解析服务 (Requirements)
  ├─ 测试点服务 (Test Points)
  ├─ 测试用例服务 (Test Cases)
  ├─ AI 任务服务 (AI Tasks)
  ├─ 模型配置服务 (Model Config)
  ├─ 自动化服务 (Automation)
  ├─ 文档模板服务 (Doc Config)
  ├─ 文档生成服务 (Doc Gen)
  └─ 状态日志服务 (Status Logs)

AI 能力层
  ├─ LLM 网关 (OpenAI Compatible API)
  ├─ Prompt 模板
  ├─ Agent 编排
  ├─ 文档解析
  └─ JSON 响应解析

数据层
  └─ SQLite (MVP阶段) / PostgreSQL (生产环境)
```

## 3. 技术选型

| 层级 | 技术方案 | 说明 |
|---|---|---|
| 前端 | React 18 + TypeScript + Vite | 现代化前端工具链 |
| UI 组件 | Lucide React (图标) + 自定义组件 | 轻量级 UI 方案 |
| 状态管理 | React Context + useReducer | 轻量级状态管理 |
| 后端 | FastAPI + SQLAlchemy (Async) | 异步高性能框架 |
| 数据库 | SQLite (MVP) / PostgreSQL (生产) | MVP阶段使用轻量数据库 |
| 缓存 | Redis (生产环境可选) | 用于任务状态、临时结果 |
| 认证 | JWT (PyJWT) | 无状态认证 |
| 密码加密 | bcrypt | 安全密码存储 |
| AI 网关 | OpenAI Compatible API | 统一模型调用 |
| HTTP 客户端 | httpx | 异步 HTTP 请求 |

## 7. AI 任务状态流

```text
等待 → 执行中 → 成功
            ↘ 失败 → 可重试
```

长任务必须异步化，前端通过轮询获取任务状态。

## 8. 安全设计

- **认证**: JWT 无状态认证，Token 有效期 24 小时
- **密码**: bcrypt 加密存储，兼容旧的 SHA256 哈希
- **授权**: 基于用户ID的数据隔离，每个用户只能访问自己的项目
- **API Key**: 对称加密存储 (XOR + Base64)
- **CORS**: 可配置的跨域策略
- **文件上传**: 类型验证、大小限制
