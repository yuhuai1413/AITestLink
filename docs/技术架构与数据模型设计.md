# AITestLink 技术架构与数据模型设计

> 更新时间：2026-07-18

## 1. 架构定位

AITestLink 当前是完整前后端系统，采用 React + FastAPI + SQLAlchemy Async 的分层架构。系统围绕测试数据链路设计，核心是保证需求、测试点、测试用例、自动化脚本、执行结果和文档之间可追溯。

## 2. 总体架构

```text
浏览器前端 React
  ├─ 登录/注册/个人设置
  ├─ 首页驾驶舱
  ├─ 项目空间
  ├─ 文档配置
  ├─ 模型配置
  └─ 用户管理

后端 FastAPI
  ├─ Auth Router
  ├─ Project Router
  ├─ File / Requirement Router
  ├─ Test Point / Test Case Router
  ├─ AI Task Router
  ├─ Environment Router
  ├─ Automation Router
  ├─ Doc Config / Doc Gen Router
  └─ Model Config Router

业务服务层
  ├─ DocumentService
  ├─ TestDesignService
  ├─ AIService
  ├─ UIRecognitionService
  ├─ AutomationService
  ├─ DataLineageService
  ├─ DocTemplateParser
  └─ DocTemplateRenderer

数据层
  ├─ SQLite / SQLAlchemy models
  ├─ uploads 文件目录
  └─ doc-templates 模板目录

外部能力
  ├─ OpenAI Compatible LLM
  ├─ Playwright / pytest
  ├─ python-docx
  └─ openpyxl
```

## 3. 技术选型

| 层级 | 技术 | 说明 |
|---|---|---|
| 前端 | React + TypeScript + Vite | 单页应用和模块化开发 |
| 样式 | 自定义 CSS 组件体系 | 统一 UI 风格和表格、弹窗、下拉组件 |
| 状态 | React Context + Hooks | 项目详情页共享数据和 AI 任务状态 |
| 后端 | FastAPI | REST API、后台任务、Swagger 文档 |
| ORM | SQLAlchemy Async | 异步数据库访问 |
| 数据库 | SQLite | 当前开发和本地部署默认 |
| 认证 | JWT | 无状态登录态 |
| AI | OpenAI Compatible API | 多节点模型配置 |
| 文档 | python-docx | Word 模板解析和渲染 |
| Excel | openpyxl | 后端生成标准 `.xlsx` |
| 自动化 | Playwright / pytest | UI/API 自动化脚本生成与执行 |

## 4. 核心链路

```text
FileAsset
  → Requirement
  → TestPoint
  → TestCase
  → AutomationScript
  → ExecutionRun
  → Data Summary / Document Generation
```

设计原则：

- 下游数据必须有上游来源。
- 上游未评审通过，下游不能生成。
- 上游重新生成后，下游数据标记为失效。
- 输入资料删除时按链路清理或提示下游影响。
- 中间环节不提供随意删除，避免破坏 100% 覆盖关系。

## 7. 关键数据模型

| 模型 | 作用 |
|---|---|
| Project | 项目主表，记录项目名称、测试类型、状态、优先级和描述 |
| FileAsset | 输入资料表，记录上传文件、解析状态和存储路径 |
| Requirement | 需求表，记录需求编号、模块、功能点、规则、风险、评审和有效状态 |
| TestPoint | 测试点表，记录需求关联、类型、优先级、自动化适配、评审和有效状态 |
| TestCase | 测试用例表，记录步骤、数据、预期、测试端、地址、角色、执行结果和评审状态 |
| EnvironmentConfig | 环境配置，记录 Web / APP 地址、验证码、超时、重试和默认环境 |
| TestAccount | 测试账号，记录账号、角色和所属环境 |
| UISnapshot | 系统识别结果，保存页面结构、元素、问题和错误 |
| AutomationScript | 自动化脚本，保存框架、语言、代码、评审和状态 |
| ExecutionRun | 执行记录，保存日志、结果、失败摘要和执行状态 |
| DocTemplate | 文档模板，保存模板文件、结构、哈希和解析状态 |
| DocGenStatus | 文档生成状态，记录各类文档生成进度 |
| ModelConfig | 模型配置，记录供应商、模型、API Key、Endpoint、连接状态 |

## 8. AI 输出校验

所有核心 AI 输出都需要结构化校验：

- 需求解析结果必须包含模块、功能点、规则等字段。
- 测试点必须关联需求。
- 测试用例必须关联测试点和需求。
- 脚本不能只有登录步骤，必须覆盖用例目标。
- 文档生成如果走 AI 兜底，必须符合系统 schema。

当模型返回多余字段或缺失字段时，后端返回用户可理解的错误，不直接暴露 Pydantic 原始异常。

## 9. Excel 与文档生成

测试用例导出已经迁移到后端，使用 `openpyxl` 生成真实 `.xlsx`：

- 表头差异化。
- 合理列宽。
- 短字段水平居中。
- 长字段自动换行。
- 垂直居中。
- 冻结表头。
- 开启筛选。

文档生成使用 `python-docx`：

- 上传模板时解析结构并缓存。
- 生成时复制原模板。
- 替换项目字段和占位符。
- 按表头识别需求、测试点、测试用例表格并填充。
- 保留原模板样式。

## 10. 部署形态

开发环境：

```text
前端：localhost:5173
后端：localhost:8001
数据库：server/aitestlink.db 或配置的 SQLite 文件
```

生产部署可使用：

- Nginx 提供前端静态资源。
- Nginx 反向代理 `/api` 到 FastAPI。
- PM2 / gunicorn / uvicorn 管理后端进程。
- uploads 和 doc-templates 作为持久目录。
