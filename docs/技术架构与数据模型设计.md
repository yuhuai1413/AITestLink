# AI 软件测试平台技术架构与数据模型设计

## 1. 架构目标

技术架构需要支持 AI 任务编排、文档解析、测试资产管理、自动化执行和质量数据分析。第一版应保持架构清晰，避免过早复杂化；但核心数据链路必须从一开始设计完整。

核心链路：

```text
需求 → 测试点 → 测试用例 → 执行记录 → 缺陷 → 回归记录 → 测试报告
```

## 2. 总体架构

```text
前端应用
  ├─ 首页驾驶舱
  ├─ 项目空间
  ├─ 需求解析
  ├─ 测试设计
  ├─ 用例管理
  ├─ 执行中心
  ├─ 自动化中心
  ├─ 缺陷中心
  └─ 报告中心

后端服务
  ├─ 项目服务
  ├─ 文件服务
  ├─ 需求解析服务
  ├─ 测试设计服务
  ├─ 用例服务
  ├─ 执行服务
  ├─ 缺陷服务
  ├─ 自动化服务
  ├─ 报告服务
  └─ AI 编排服务

AI 能力层
  ├─ LLM 网关
  ├─ Prompt 模板
  ├─ Agent 编排
  ├─ RAG 检索
  ├─ 文档解析
  └─ 日志/截图分析

数据层
  ├─ PostgreSQL
  ├─ Redis
  ├─ MinIO/S3
  ├─ Vector DB
  └─ 执行日志存储

集成层
  ├─ 禅道/Jira/TAPD
  ├─ GitLab/GitHub
  ├─ Jenkins/GitHub Actions
  ├─ 企业微信/飞书
  └─ SSO/LDAP
```

## 3. 技术选型建议

| 层级 | 推荐方案 | 说明 |
|---|---|---|
| 前端 | React + TypeScript + Ant Design | 适合后台管理和复杂表格 |
| 后端 | FastAPI 或 Spring Boot | FastAPI 更适合快速集成 AI，Spring Boot 更适合企业级标准化 |
| 数据库 | PostgreSQL | 支持复杂关系和 JSONB 扩展 |
| 缓存 | Redis | 用于任务状态、队列状态、临时结果 |
| 文件存储 | MinIO 或 S3 | 存储文档、截图、日志、报告 |
| 向量库 | pgvector、Milvus 或 Qdrant | 存储需求、用例、缺陷知识向量 |
| 自动化 | Playwright + pytest | Web UI 自动化优先 |
| 接口测试 | pytest + requests/HTTPX | 支持数据驱动和断言 |
| 任务队列 | Celery、RQ 或 BullMQ | 执行 AI 解析、报告生成、自动化任务 |
| AI 网关 | OpenAI compatible API 网关 | 统一模型调用、审计和降级 |

## 4. AI 服务设计

### 4.1 LLM 网关

负责统一管理模型调用。

能力：

- 模型供应商适配。
- Token 统计。
- 超时控制。
- 重试机制。
- 审计日志。
- 敏感信息脱敏。
- Prompt 版本管理。

### 4.2 Agent 编排

建议拆成多个专职 Agent。

| Agent | 输入 | 输出 |
|---|---|---|
| 需求解析 Agent | PRD、FS、原型、接口文档 | 需求解析表、待确认问题 |
| 测试设计 Agent | 需求解析表 | 测试点、测试数据建议 |
| 用例生成 Agent | 测试点、业务规则 | 测试用例 |
| 用例评审 Agent | 测试用例、需求解析表 | 评审问题、遗漏场景 |
| 自动化 Agent | 测试用例、页面信息、接口文档 | 自动化脚本 |
| 执行分析 Agent | 日志、截图、trace、接口响应 | 失败原因分类 |
| 缺陷生成 Agent | 失败用例、实际结果、日志 | 标准缺陷单 |
| 报告 Agent | 执行数据、缺陷数据、风险数据 | 测试报告 |

### 4.3 RAG 检索

知识库检索用于增强 AI 输出质量。

可检索内容：

- 历史需求。
- 历史测试用例。
- 历史缺陷。
- 历史报告。
- 自动化脚本。
- 业务规则。
- 测试规范。

典型场景：

- 新需求生成用例时，检索相似历史需求和用例。
- 缺陷分析时，检索相似历史缺陷。
- 回归推荐时，检索历史高风险模块。

## 7. AI 任务状态流

```text
待执行 → 执行中 → 成功
              ↘ 失败 → 可重试
```

长任务必须异步化，前端通过轮询或 WebSocket 获取任务状态。

## 8. 安全与审计

- 上传文件需要权限校验。
- AI 输入前进行敏感信息识别和脱敏。
- AI 输出需要保留生成记录和 Prompt 版本。
- 重要操作保留审计日志。
- 自动化执行环境和测试数据隔离。
- 缺陷、日志、截图按项目权限访问。

## 9. 部署建议

MVP 阶段可以采用单体后端 + 独立 AI Worker 的结构。

```text
Web 前端
后端 API 服务
AI Worker
PostgreSQL
Redis
MinIO
```

后续规模扩大后，再拆分为项目服务、用例服务、自动化服务、AI 服务和报告服务。

## 10. 开发优先级

| 阶段 | 后端重点 | 前端重点 |
|---|---|---|
| 第一阶段 | 项目、文件、AI 任务、需求解析、用例生成 | 项目列表、上传、解析结果、用例表格 |
| 第二阶段 | 执行记录、缺陷、报告 | 执行中心、缺陷中心、报告中心 |
| 第三阶段 | 自动化脚本、执行编排、日志分析 | 自动化任务、执行报告、失败分析 |
